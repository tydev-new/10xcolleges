# Schema: tracker.md

Owner: `app-tracker`
Class: **Derived**

Location: `students/<slug>/out/tracker.xlsx`

`tracker.xlsx` is the compiled operational spreadsheet for a student's college application campaign. It is generated by `scripts/make_tracker.py` from `meta.json` and `config/calendar.json`. It is strictly a **Derived** artifact — agents and users must **never hand-edit** the `.xlsx` file directly; all updates are made to `meta.json` and regenerated.

---

## `tracker.xlsx` — owned by app-tracker

### Workbook Layout & Sheets

The workbook contains five sheets formatted with professional styling (navy headers `#1F3864`, white text, zebra banding `#F2F5FA`, thin borders `#BFBFBF`, frozen panes, and live Excel formulas):

```
tracker.xlsx
├── Read Me         (Tab 0: Cycle orientation, color legend, instructions)
├── Applications    (Tab 1: College roster, deadlines, live countdown, status)
├── Tasks           (Tab 2: 12-week backwards-planned to-do list)
├── Recommenders    (Tab 3: Faculty & counselor recommendation tracking)
└── Key Dates       (Tab 4: Cycle-wide chronological milestones)
```

---

### Sheet 1: `Read Me` (Index & Legend)

- **Purpose:** Orients the student and parents, displays the generation timestamp, explains the backwards planning philosophy, and provides the conditional formatting color key.
- **Header:** `# Application Tracker — <Student Name>`
- **Color Legend:**
  - **Green:** Submitted application / completed task / > 29 days left.
  - **Amber:** Approaching deadline (14–29 days left) / task due within 7 days.
  - **Red:** Urgent deadline (< 14 days left) / overdue incomplete task.
  - **Grey:** Past deadline.

---

### Sheet 2: `Applications` (Application Roster)

- **Purpose:** High-level view of all institutions on the student's list, sorted chronologically by deadline and tier.
- **Freeze Panes:** Row 1 frozen (`A2`).
- **Columns (14):**

| Col | Header | Type | Format / Calculation / Validation | Description |
|---|---|---|---|---|
| A | `College` | Text | Width 30, Left-align | Official institution name |
| B | `Tier` | Dropdown | Width 10, Options: `safety`, `target`, `reach` | Selectivity category |
| C | `Plan` | Text | Width 8 | Decision plan (`EA`, `ED`, `ED II`, `REA`, `RD`, `Rolling`) |
| D | `Deadline` | Date | Width 12, `yyyy-mm-dd` | Verified institutional deadline |
| E | `Days Left` | Formula | Width 10, `=IF(D{row}="","",D{row}-TODAY())` | Live countdown updating dynamically |
| F | `App Type` | Text | Width 14 | Platform (`Common App`, `Coalition`, `Institutional`) |
| G | `Status` | Dropdown | Width 18, Options: `considering`, `committed-to-apply`, `in-progress`, `submitted`, `decided`, `withdrawn` | Current application lifecycle state |
| H | `Essays Req'd`| Integer | Width 12 | Total number of required supplements |
| I | `Essays Done` | Integer | Width 12 | Number of completed supplements |
| J | `Counselor Ltr`| Text | Width 13, `yes` or `no` | Whether school counselor rec is needed |
| K | `Teacher Recs`| Integer | Width 13 | Number of teacher letters requested |
| L | `Test Policy` | Text | Width 14 | Testing policy (`required`, `test-optional`, `test-blind`) |
| M | `Fee` | Currency | Width 10 | Application fee amount |
| N | `Notes` | Text | Width 40 | Specific warnings (e.g. scholarship priority cutoff) |

- **Conditional Formatting Rules:**
  1. `Days Left < 0`: Grey fill (`#E7E6E6`).
  2. `0 <= Days Left <= 13`: Red fill (`#FFC7CE`).
  3. `14 <= Days Left <= 29`: Amber fill (`#FFEB9C`).
  4. `Days Left > 29`: Green fill (`#C6EFCE`).
  5. `Status = "submitted"`: Entire row highlighted Green (`#C6EFCE`).

---

### Sheet 3: `Tasks` (Backwards-Planned Action Items)

- **Purpose:** The actionable engine. Generated by working **backwards** from each college's deadline using the 12 offsets defined in `config/calendar.json`.
- **Auto-Filter:** Enabled across all columns (`A1:H{N+1}`).
- **Columns (8):**

| Col | Header | Type | Format / Calculation / Validation | Description |
|---|---|---|---|---|
| A | `Due` | Date | Width 12, `yyyy-mm-dd` | Calculated milestone date |
| B | `Days Left` | Formula | Width 10, `=A{row}-TODAY()` | Live days remaining until task due date |
| C | `Task` | Text | Width 52 | Actionable task description with institution name |
| D | `College` | Text | Width 26 | Associated college or `— all —` |
| E | `Category` | Text | Width 12 | `Decision`, `Recs`, `Research`, `Essays`, `Testing`, `Admin`, `Aid`, `Submit` |
| F | `Owner` | Text | Width 10 | `Student` or `Family` |
| G | `Status` | Dropdown | Width 14, Options: `not started`, `in progress`, `blocked`, `done`, `skipped` | Task completion status |
| H | `Notes` | Text | Width 34 | Guidance notes, warnings, or compression tags |

- **Conditional Formatting Rules:**
  1. `Days Left < 0 AND Status <> "done"`: Red fill (`#FFC7CE`) (overdue).
  2. `Status = "done"`: Green fill (`#C6EFCE`).
  3. `0 <= Days Left <= 7`: Amber fill (`#FFEB9C`) (due this week).

### Regeneration Invariants

1. **Unidirectional Data Flow:** Never modify `tracker.xlsx` directly. Always update `meta.json` and execute:
   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/make_tracker.py" students/<slug>
   ```
2. **Strict Date Parsing:** All dates in `meta.json` must be valid ISO `YYYY-MM-DD`. Malformed dates abort the build immediately to prevent missing tasks.
3. **Graceful Compression:** For runways shorter than 10 weeks, tasks are compressed proportionally without dropping essential review steps.
